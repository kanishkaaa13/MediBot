# MediBot – Webots hospital simulation (code-generated)

Everything (world, walls, AprilTags, robot, obstacle) is generated by `generate_world.py`.
You only open the world in Webots and press Run.

## 1. Setup (about 10 minutes, Windows)
1. Install **Webots** (R2023b or newer) and **Python 3.9–3.12**.
2. In Webots: *Tools → Preferences → Python command* → `python` (must be the same Python you pip-install into).
3. Unzip this folder, open a Command Prompt inside it, and double-click / run `setup_windows.bat`.
   It installs numpy + opencv-python + matplotlib, generates the world, and runs a self-test.
   You should see `ALL TESTS PASSED`.
4. In Webots: *File → Open World…* → `worlds\medibot.wbt`. Press **Run** (▶).

## 2. Controls (click on the 3D view first so it gets keyboard focus)
| Key | Action |
|---|---|
| **S** | Start delivery HOME → WARD-3B (A* route is drawn as a blue line) |
| **B** | Put the trolley on the route (press before or during the mission) |
| **U** | Remove the trolley |
| **F / R** | Confirm face / RFID at the ward (simulated; auto-confirms after 8 s) |
| **T** | Turn AprilTag correction ON/OFF (only while IDLE) |
| **X** | Reset robot to HOME |

State machine: IDLE → NAVIGATE → APPROACH → VERIFY → DELIVER → RETURN.
The on-screen overlay shows state, destination, ultrasonic readings, pose error and the last tag correction.
The Webots console prints the `[EKF] ... error before / after` lines and `[REPLAN]` events.
To see the camera: right-click the 3D view → *Overlays → Camera Devices → camera*.

## 3. Demo recording (3 runs, ~5 minutes)
Use *Tools → Movie recording* (or the camera icon). Press **X** between runs.
1. **Normal run**: `S`, let it deliver and return.
2. **Obstacle run**: `B`, then `S` (or press `B` while it is driving). The robot stops < 30 cm from the trolley,
   waits 2 s, marks the corridor blocked, replans through the ICU, delivers, returns.
3. **Drift comparison**: `T` (tags OFF), then `S`. Compare with a run with tags ON (`python plot_log.py`
   makes `localisation_comparison.png` – your best slide). Every mission writes a CSV into
   `controllers\medibot_controller\logs`.

## 4. How it works
- `generate_world.py` – builds `worlds/medibot.wbt`, real tag36h11 PNGs, and `config.json` (graph + tag table).
  Change a node position or a tag position there and re-run it; the controller follows automatically.
- `medibot_core.py` – A*, EKF (x, y, θ), AprilTag detection with OpenCV ArUco `DICT_APRILTAG_36h11` and pose recovery.
- `medibot_controller.py` – sensors, odometry, state machine, obstacle logic, keyboard, overlay.
- The EKF predicts from wheel encoders + gyro and corrects when a tag is seen. Odometry is **deliberately imperfect**
  (3 % wheel-radius error, gyro bias) so drift is visible; the real physics position is read only to *log* the true error.

## 5. If something breaks
| Symptom | Fix |
|---|---|
| `ERROR: run pip install ...` in console | Webots uses a different Python: set *Preferences → Python command* to the one you pip-installed into |
| Wheels look vertical / robot spins on the spot | In `generate_world.py` function `wheel()`, change `rotation 1 0 0 1.5708` to `rotation 0 0 1 0`, re-run |
| Robot never sees tags (no `[EKF]` lines with tags ON) | Open the camera overlay; check tag boards are visible. Raise `max_dist` in `TagLocalizer.measure` |
| Robot wanders badly / hits wall | Lower `CRUISE_V` in the controller (0.30 → 0.2) |
| Webots complains about the world file | Send me the exact console error text |

## 6. Honest scope note (for your teachers)

for face/RFID/dashboard. Numbers it prints are simulation results, not measurements from the real robot.
